# ralgruM Desktop

ralgruM is a native GPUI music player. The application, networking, audio
decryption, streaming, downloads, device identity, Discord Rich Presence,
Windows tray integration, and embedded web views are implemented in Rust.

## Repository layout

- `src/` contains the application source.
- `assets/` contains embedded cursors, icons, and third-party artwork.
- `src/lyrics/core/` contains the lyrics parsing, matching, and provider modules.
- `scripts/run-gpui.ps1` builds and optionally launches the Windows app.
- `target/` is generated by Cargo and is not tracked.

## Prerequisites (Windows)

- Rust stable with the MSVC toolchain
- Microsoft C++ Build Tools with the Desktop development with C++ workload
- A Windows SDK installed through Visual Studio Build Tools
- WebView2 Runtime for the embedded web authentication views
- PowerShell 5.1 or newer

## Build and run

From the repository root:

```powershell
cargo run --locked
```

To build and launch through the helper script, stop any existing GPUI process,
and capture launcher output under the local application log directory:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run-gpui.ps1
```

Use `-BuildOnly` for a build without launching the executable, or `-Release`
for an optimized release build:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run-gpui.ps1 -BuildOnly
powershell -ExecutionPolicy Bypass -File scripts\run-gpui.ps1 -Release
```

## Release build

Bump the package version, build the optimized Windows executable, and copy it
to `dist/` as `ralgruM.exe`:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-release.ps1
powershell -ExecutionPolicy Bypass -File scripts\build-release.ps1 -Bump Patch
powershell -ExecutionPolicy Bypass -File scripts\build-release.ps1 -Bump Minor -Prerelease beta.1
powershell -ExecutionPolicy Bypass -File scripts\build-release.ps1 -Version 1.2.3
```

Versions follow strict Semantic Versioning 2.0.0. The new version must be
higher than the current one unless `-Force` is passed, and `-NoBuild` updates
the version files without building. Promoting a prerelease such as
`1.2.3-alpha` to its release uses an explicit `-Version 1.2.3`.

## Checks

```powershell
cargo fmt --all -- --check
cargo metadata --locked --no-deps
cargo check --locked --all-targets
cargo test --locked --all-targets
```

These commands use the selected backend. For a real-backend run, place the
private checkout at the default path described below, or select it with
`RALGRUM_MURGLAR_PRIVATE_DIR`. To check and test the public stub instead, select
a directory that has no `mod.rs`:

```powershell
$env:RALGRUM_MURGLAR_PRIVATE_DIR = 'target/no-private-backend'
cargo check --locked --all-targets
cargo test --locked --all-targets
Remove-Item Env:RALGRUM_MURGLAR_PRIVATE_DIR
```

Removing the override restores the default backend selection.

The release profile enables thin LTO, size optimization, symbol stripping, and
a single codegen unit for a compact executable.

## Login and device persistence

On Windows, ralgruM stores its native session under `%APPDATA%\ralgruM` in
`auth_session.dat` and `auth_session.backup.dat`. Both copies use Windows
current-user DPAPI encryption in a versioned, size-bounded container. The
serialized session is limited to 64 KiB and the encrypted payload to 256 KiB.
DPAPI protects stored data in the Windows user's context; it does not protect
against code running as that user or guarantee that files cannot be deleted
or replaced. Non-Windows production builds have no plaintext storage fallback.

Existing configuration can be copied from `%APPDATA%\app.ralgrum.player`
without overwriting files already present in the active directory. If neither
encrypted session file exists, a one-time migration accepts recognized legacy
session JSON from the active directory or the distinct old configuration
directory. Existing encrypted files take precedence: a valid copy repairs a
missing or invalid counterpart, and an unreadable encrypted pair produces an
error rather than falling back to plaintext.

The legacy `auth_session.json`, `auth_session.backup.json`, and `deezer_sid.txt`
files are removed from the active directory and the distinct old configuration
directory only after both encrypted copies have been successfully written or
validated and repaired as needed. Cleanup does not search other directories,
and file deletion is not a secure-erasure guarantee.

## Private backend boundary

The public application treats provider-specific account, device identity, and
media operations as an opaque private-backend boundary. Protocol details and
device representation are not part of the public application contract.

The default private checkout path, `src/murglar_backend/implementation/`, is
ignored by Git. `build.rs` selects its `mod.rs` when present. Set
`RALGRUM_MURGLAR_PRIVATE_DIR` to select another checkout directory; relative
paths are resolved from the repository root, and absolute paths are accepted.

If the selected directory has no `mod.rs`, the build uses the public
`src/murglar_backend/stub.rs` instead. The private checkout is therefore not
required to compile the public tree. The stub performs no private-backend
network requests: account and identity operations report unavailability,
and media resolution and probing report unavailability or cancellation.
It does not provide a working replacement for the private service.
